这套流程不是自包含的，它依赖以下本机资源。**换到新环境后，必须逐项核对并重建，否则流程会卡在第一步。**

## 2. 流程骨架（总览）

```
一轮：检索确认 → 下载 → GPU 转换 → 双读精读 → 审计 → 锁定
二轮：雪球下载 → GPU 转换 → 双读精读 → 增量审计
终答：叠加 → 终审 → HTML
```

收到调研请求后，先与用户确认主题（一句话），然后按流程执行。**默认执行完整调研流程**（用户另有要求可调整）。所有系统级操作（创建文件夹、打开浏览器、写入文件）均需在用户确认或放行后执行。

## 4. 一轮 · 检索

1. **问题拆解**：2-5 个递进式子问题（避免平面拆分，后问题引用前问题结论）；判别场景类型（literature_search / concept_explain / method_compare / paper_interpret / research_status / tech_roadmap）；判定归纳轴（能力 / 任务 / 硬件 / 时间线 / 对比 / 课题组，模糊默认能力维度）
2. **★ 闸门**：拆解结果 + 场景 + 归纳轴报告用户，等明确确认（确认 / OK / 可以 / 直接搜吧）。未确认不得进入搜索
3. **关键词展开**：五维（传统分支 / 跨界交叉 / 新涌现概念 / 核心研究者 / 新兴研究者）每维 2-5 个中英关键词，每维至少 1 个基础单关键词
4. **搜索**：
   - 期刊站内搜索（9 家，`site:` 限定，关键词统一）：nature.com / link.springer.com / science.org / sciencedirect.com / ieeexplore.ieee.org / pnas.org / journals.sagepub.com / iopscience.iop.org / onlinelibrary.wiley.com
   - 泛搜索兜底（无 site）
   - CrossRef API 辅助（ISSN 分路，多 ISSN 必须重复键写法 `issn:a,issn:b`；逗号合并返回 400）
5. **核实链**：有摘要即可核实（搜索结果自带元数据）→ 缺摘要 CrossRef 查 DOI → 仍存疑 browser
6. **过滤**：白名单（zhu-journals.md，排除刊禁用）→ 排序（年份降序 → NS 子刊优先 → 被引降序）→ ≤5 篇/刊 → 综述识别 📖 → 经典补刀可选
7. 输出文献清单（标题 / DOI 直达链接 / 一句话简介 / ✅📖 标注），存档 round1_list.yaml（可选）

---

## 5. 一轮 · 库内匹配分流（文献清单确认后执行）

1. 读 `E:\Library-Manage\new-library\文献索引.md` 构建查找表
2. 清单切片（每片 5-8 篇）→ 多子代理并行：逐篇 DOI 匹配 + 按编号定位 md 实体 + 读头部判断形态（含 Abstract / 章节标题 → 全文型；仅「研究问题/目标」等笔记头 → 笔记型）→ 返回 `{DOI} | {档位} | {md路径} | {依据}`
3. 汇总分档（对话清单显式标记）：
   - `[库内原文]` md 含全文正文 → 直接进双读，输入 = md 全文
   - `[需下载]` 其余一律（含笔记型 md、未命中）→ Edge 打开 + 用户下载
4. Edge 只打开 `[需下载]`
5. ★ 精读笔记不算原文（六维答案随调研问题漂移），不得作为双读输入，一律走 `[需下载]`

## 6. 一轮 · 下载（仅 [需下载] 文献）

1. 提取全部 DOI → Edge 批量打开（一次传参）：
   ```
   & "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" ($dois | ForEach-Object { "https://doi.org/$_" })
   ```
   （提权放行 1 次）
2. 用户逐个下载 → 拖进对话 → PDF 原件存 `{主题}\r1\`
3. **GPU 转换**：PDF 收集完毕后，用 `E:\PDF2md\GPU转换.bat` 批量转 md（把 PDF 文件或整个文件夹拖到 bat 图标上，输出目录填 `{主题}\r1\`，转换后的 md 与 images 目录直接落位；或命令行 `python pdf2md_gpu.py 文件1 文件2 -o 输出目录`）

## 7. 一轮 · 双读精读

每篇论文**并行**两个实例，输入同一份 MinerU 转换的 md 全文（GPU 版转换；md 中可疑或缺失处回 PDF 复核）：

**主读**：综述 → 观点提炼模板；普通 → 六维 + 思考三问模板（模板见第 11 节）

**验证读**：按文献类型选择问题版本：

普通论文版：
```
1. 一句话贡献是什么？
2. 方法的核心机制/关键假设是什么？
3. 最大的弱点或争议点在哪？
4. 它和调研主题的关系（回答了哪个子问题）？局限是否影响使用？
```

综述版（综述无实验设置/核心机制，问题不同）：
```
1. 综述覆盖了哪些方法/技术流派？分类框架是什么？
2. 有没有明显遗漏的流派或重要工作？（对比你已知的领域知识）
3. 综述自身的关键论断或分析倾向是什么？可信度如何？
4. 综述引用了哪些关键原始文献（雪球候选）？其中哪些值得纳入下一轮？
```

**仲裁**（主读方执行）：验证读提到主读漏了 → 补入归档标「验证读补充」；矛盾 → 回原文裁定；一致 → 归档标「✅双读一致」。

**归档**：每篇立即归档 `r1-{序号}_中文简短标题_年份.md`（模板见第 11 节），R1 全部文献必须全部归档。

**汇总**：初步回答.md（子问题优先 ≥2 子问题为一级章节、归纳轴兜底；递进子问题先列前序结论；每技术点 [N] 引用；交叉验证 ✅多源一致 / ⚠️存在分歧 / 📌单源；缺失维度写明「未找到充分信息」）

---

## 8. 一轮 · 审计对抗

1. 派出审计官（laodeng 实例，read 权限）：
   - 审前：全文覆盖度检查（引用须分布论文各部位，全在前 3 页 → 回溯重读）
   - 逐条 [N] 回归档定位（连字归一化：ef fi ciently → efficiently）
   - 分类：✅ 原文确认 / ⚠️ 部分匹配 / 🔄 综述代引 / 🚫 无原文支撑
2. 研究员修订：删 🚫 / 改 ⚠️ / 替换 🔄（溯源原始 DOI）
3. 循环至 🚫=0 且 ⚠️ 全修正
4. **锁定**：审计报告 = 禁改清单；修订后初步回答 = 锁定基底

---

## 9. 二轮 · 雪球

1. 从 📖 综述参考文献挖（≥2 篇共同引用优先 / 独立成段讨论 ≥3 句次之 / 禁仅凭标题）
2. 逐篇核实 + 摘要判断，与第一轮去重（DOI 标准化）
3. Edge 再开一轮（放行 + 下载）→ PDF 存 `r2\` → GPU 转换 → 双读精读（同上）→ 归档 `r2-*.md`（R2 全部归档）
4. 增量审计：新增声明逐条对照 + 防回退（已删内容重现按 🚫）+ 覆盖度复检 → 🚫=0

---

## 10. 终答

1. 研究员携带禁改清单 → 只叠加第二轮内容，第一轮保持锁定版本不变 → 8 项自查（DOI 可验证 / 结论来自精读 / 陈述有原文 / 全量已读 / 覆盖全文 / 无代引 / 雪球已验 / 缺文已声明）
2. 最终回答.md：搜索范围概述、两轮文献总览、综述分析、核心发现（子问题优先）、交叉验证汇总、GB/T 7714 参考文献（标注轮次与等级 (A)/(D)）、缺文清单
3. 终审通过 → 生成最终回答.html（🚨 不可跳过，100% 基于已审计内容，语义化 HTML5，引用上标，移动端适配）
4. 汇报：文献清单、归档数、审计可信度、产物位置

## 附 · 资源说明

- **MinerU GPU 转换（精读输入主通道）**：`E:\PDF2md\GPU转换.bat` + `pdf2md_gpu.py` + `pdf2md.py`（三个文件必须同目录）。把 PDF 文件或文件夹拖到 bat 图标即批量转换，输出目录回车用默认或自填；底层为 MinerU CUDA 管线，RTX 3060 6GB，速度比 CPU 快 3~8 倍，公式/表格/版面识别完整，转换后自动清理中间产物，批量时模型只加载一次。模型已缓存本地。
